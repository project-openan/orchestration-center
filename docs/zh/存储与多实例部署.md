# 统一存储与编排中心多实例部署

## 已实现的存储范围

`persistence_mode=file|postgresql|mysql` 统一控制 PSOP、PreFlow、普通执行记录、方案包解析记录与工作流关联、沙箱报告/模板、持久任务与事件。
内置模板仍为 `samples/` 中的只读资源；原始 PDF 目前仍是解析临时文件，不新增长期附件保存。
SQL 模式的账号会话保存在共享数据库，仅保存 token 摘要；改密、账号删除和会话撤销跨实例生效。文件模式保留单密码账号与进程内会话，限单进程使用。

新增运行数据使用 `orchestration_documents`（namespace/key/revision/payload）与显式事务门禁表。SQL 的 PSOP/执行记录仍使用原有表；同一命令通过借用事务连接统一提交。业务应用不需要自行选择数据库品牌。
方案包与 PSOP 的关联共同提交；生成期间源方案包变化返回 409。未提供事务契约的第三方 SAVE_PSOP handler 不能参与这个原子命令，须改用事务感知的仓储适配器。

## 先迁移，再启动副本

不要删除旧 `data`。停止使用该数据目录的文件写入进程，备份数据和数据库，然后在仓库根目录执行：

```powershell
python -m scripts.migrate_operational_storage --source-root ./data --mode mysql --dry-run
python -m scripts.migrate_operational_storage --source-root ./data --mode mysql --initialize
```

PostgreSQL 将 `mysql` 换为 `postgresql`。连接与秘密沿用现有数据库配置系统，不把密码放入命令行。`--initialize` 是受控的单次 schema 初始化；副本启动不应并发运行迁移。
迁移对象是 PreFlow、方案包、沙箱报告和桩模板；已有 SQL PSOP、执行记录和用户不在此脚本中重复导入。历史文件如果保存在 `orchestrate/data` 等旧工作目录，可将它另作 `--source-root`，先检查 dry-run 结果与冲突。
迁移保留原文件；已有不同内容的目标记录报冲突，不覆盖。重复执行核对实际目标内容，不凭 success 检查点跳过；dry-run 不写目标。既有历史对象继续沿用共享工作区访问策略，新运行使用稳定账号主体归属。
普通 file→SQL 工作流/执行历史的全量迁移需沿用仓库现有导入/备份工具；本脚本不会假装已经迁移那些表。切换后的新写入须先导出核对再回退，不能只改 persistence_mode。

配置示例（实际地址和秘密由部署环境提供）：

```properties
persistence_mode=mysql
deployment_mode=cluster
execution_lease_seconds=30
execution_max_active=16
execution_deadline_seconds=3600
```

环境别名为 `PERSISTENCE_MODE`、`ORCH_DEPLOYMENT_MODE`。文件模式可通过 `ORCH_DATA_DIR` 指定绝对数据根目录。同一机器/同一路径只允许一个文件写进程；cluster+file 会拒绝启动。
所有副本必须连接同一权威主库，使用一致的身份、模型/角色配置和协议版本。SQL 集群启动检查新 schema 已存在，缺失时拒绝启动；API 进程同时承担可横向分担的执行协调工作。

## 执行 API 与前端行为

新接口在 `/rest/v1/orchestrate` 和 `/api/v1` 下提供：

| 接口 | 含义 |
|---|---|
| `POST /runs` | 提交意图及可选 workflow_id，返回 202 和 execution_id；支持 Idempotency-Key |
| `GET /runs`、`GET /runs/{id}` | 查询本身份的任务与一致性快照；包含 as_of_seq |
| `GET /runs/{id}/events?after_seq=N` | SSE 重放；也支持 `Last-Event-ID: id:seq` |
| `POST /runs/{id}/cancel` | 请求取消，不代表远端已经停止 |

集群模式下旧 `/execute`、`/dispatch` 等执行入口适配到持久任务，需要 `Idempotency-Key` 或非秘密 `request_key` 参数。当前仓库自带的前端尚未发送该标识，因此在集群模式下这些旧入口会返回 428，直到前端更新合入；程序化调用方需自行提供稳定请求标识，EventSource 重连不会再创建任务；Last-Event-ID 重连先恢复已有事件订阅，不依赖重新发现智能体或重新读取工作流。
单实例旧 SSE 保留原来的生命周期；新 `/runs` 始终使用后台任务语义。前端收到 `execution_accepted` 后提示关闭页面只退订，停止按钮显式发取消命令；同标签页刷新会从一致性快照重新订阅，不重新执行。
游标超出事件保留窗口或历史存在缺口时明确返回冲突/stream_error，前端要求重新加载快照，不静默跳过。SSE 允许重传，客户端按事件 ID 去重。
新运行的历史查询别名也检查运行主体，不能绕过 `/runs` 的对象权限。旧记录继续属于现有共享工作区。

## 故障与边界

任务接受、幂等结果与初始执行记录共同提交；终态、结果、末事件与历史记录共同提交。worker 租约和 fencing 阻止旧执行者写回。
创建 Host 任务前先持久化唯一派发意图与实际冻结信封；有发送意图的失联任务只进入 `reconciliation_required`，不会自动创建第二个远端任务。已观察到的 Host task/context ID 会被保存供核对。
Host 的持久幂等接受、任意重启后的原任务查询和无损续订尚未获得实机保证。因此不承诺任意故障下自动接管或业务副作用恰好一次；取消后结果未知时也不能显示“已确认停止”。应使用固定、可追踪的 Host 地址，核对其任务存储能力。
沙箱的 queued 请求保存输入快照，可由其他实例在原 ID 下领取；已运行但失联的沙箱任务保留待核对状态，不盲目重跑。运行中的取消/删除保留墓碑，旧 worker 不会重新发布报告。

队列按运行类型共享并发预算，每类最多保留 128 个待领取任务；事件默认保留最近 2000 条，历史结果仍有独立摘要。单进程连接保护和限流不是集群总限流，入口还需配置统一限流。
向量索引是可重建缓存，副本应使用独立缓存路径；不要让多进程共享一个缓存 JSON 文件。
文件后端使用提交日志、原子替换和读写门禁恢复多记录命令；操作系统和文件系统的断电耐久性须另行验证，不等同于 SQL 的全部保证。
