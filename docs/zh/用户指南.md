# 编排中心用户指南

## 1. 特性介绍

编排中心是一个面向多智能体（Agent）协作的可视化编排平台，支持通过图形化工作流设计器定义 Agent 之间的调用关系与执行流程。后端基于 Python 框架解析流程并驱动 Agent 协同工作。

### 1.1 应用场景

- **多 Agent 协作流程编排**：当业务需要多个智能体协同完成复杂任务时，可通过可视化方式定义调用关系与执行顺序。
- **工作流模板管理**：支持将常用的协作流程保存为模板，便于复用和分享。
- **工作流自动生成**：根据自然语言描述或 PDF 文档自动生成工作流规划。
- **实时流程监控**：支持流式执行工作流并实时推送运行进展，便于调试和监控。

### 1.2 能力范围

对外提供以下 REST API 接口：

- **SOP 编排接口**：支持基于自然语言 SOP 文本或 PDF/TXT/MD 文件生成 PSOP 工作流。
- **意图编排接口**：根据自然语言意图描述，自动规划并生成可执行的 PSOP 工作流。
- **自动编排执行接口**：根据任务描述自动检索或生成 PSOP 并执行，返回 SSE 流式执行进度。
- **指定 PSOP 执行接口**：根据 PSOP ID 执行已知工作流，返回 SSE 流式执行进度。
- **Agent 列表查询接口**：获取系统中所有可用 Agent 及其技能信息。
- **执行结果查询接口**：根据执行 ID 查询工作流执行结果。

### 1.3 功能概览

- **可视化编排**：通过拖拽和连线完成 Agent 协作流程设计。
- **多模式创建**：支持 PDF 导入、手动编排、自然语言生成三种工作流创建方式。
- **语义检索**：根据自然语言意图检索历史工作流。
- **实时流式执行**：通过 SSE 推送执行进度。

### 1.4 实现原理

编排中心的核心工作流程见：[OpenAN快速入门的3.1.4核心验证流程章节](https://github.com/project-openan/docs/blob/main/zh/OpenAN%E5%BF%AB%E9%80%9F%E5%85%A5%E9%97%A8.md#314-%E6%A0%B8%E5%BF%83%E6%B5%81%E7%A8%8B%E9%AA%8C%E8%AF%81)。

编排中心提供 `install_service.sh` 脚本，支持将编排中心安装为 systemd 服务，便于服务管理和开机自启。

1. 配置部署参数（可选）

脚本默认配置文件位于 `etc/systemd/deploy.conf`，可根据需要修改以下参数：

| 参数名称 | 默认值 | 说明 |
| --- | --- | --- |
| INSTALL_DIR | /OpenA2A-T/orchestration-center | 服务安装目录 |
| PYTHON_PATH | {INSTALL_DIR}/venv/bin/python3 | Python 解释器路径 |
| SERVICE_NAME | orchestration-center | systemd 服务名称 |
| INSTALL_DEPS | true | 是否自动安装依赖 |

2. 创建虚拟环境

进入项目目录，创建并激活虚拟环境：
```bash
cd {安装目录}/orchestration-center
python3 -m venv venv
source venv/bin/activate
```

3. 安装服务

使用脚本安装服务（需 root 权限）：
```bash
cd {安装目录}/orchestration-center/bin
sudo ./install_service.sh install
```

脚本支持的命令：

| 命令 | 说明 |
| --- | --- |
| install | 安装 systemd 服务 |
| uninstall | 移除 systemd 服务 |
| status | 查看服务状态 |
| start | 启动服务 |
| stop | 停止服务 |
| restart | 重启服务 |
| enable | 设置开机自启 |
| disable | 禁用开机自启 |

可选参数：
- `--dir=PATH`：指定安装目录
- `--python=PATH`：指定 Python 解释器路径
- `--no-deps`：跳过依赖安装

示例：
```bash
# 指定安装目录和 Python 路径
sudo ./install_service.sh install --dir=/opt/my-orchestration --python=/usr/bin/python3

# 跳过依赖安装（已手动安装依赖时使用）
sudo ./install_service.sh install --no-deps
```

4. 启动服务

安装完成后，使用以下命令启动服务：
```bash
sudo ./install_service.sh start
```

或使用 systemctl 命令：
```bash
sudo systemctl start orchestration-center
```

5. 查看服务状态

```bash
sudo ./install_service.sh status
```

或：
```bash
sudo systemctl status orchestration-center
```

6. 查看启动日志

```bash
journalctl -u orchestration-center -f
```

如果可以看到 `Uvicorn running on http://127.0.0.1:5001` 则表示启动成功。

## 2.5 安全配置

编排中心支持多种安全配置，根据部署场景选择合适的安全级别。

### 开发模式（无安全）

用于本地开发和测试，关闭所有安全特性：

```ini
# etc/conf/server.conf
enable_https=false
verify_client=false
access_password=
persistence_mode=file
```

无登录页、无 HTTPS、无需证书，所有 API 接口开放访问。

### 生产模式（HTTPS + 登录认证）

通过 Nginx 反向代理部署（推荐）：

1. **配置 Nginx 的 CA 签名证书**
2. **在后端开启登录认证**：

   ```ini
   # etc/conf/server.conf
   enable_https=true          # 后端使用 HTTPS（如 Nginx 已处理 TLS 则可选）
   verify_client=false         # 不需要客户端证书（浏览器访问场景）
   access_password=<SHA-256哈希值>  # 设置后启用登录认证
   persistence_mode=postgresql   # 使用数据库管理用户
   ```

   生成密码哈希：
   ```bash
   python generate_access_password.py
   ```

3. **用户管理与注册**：当 `persistence_mode=postgresql` 时，系统首次启动会自动创建默认 `admin` 用户（密码：`OpenAN@2026`）。新用户可通过登录页的注册链接自行注册。`file` 模式下不支持注册，仅使用 `access_password` 配置的密码。

### 高安全模式（mTLS + HTTPS + 登录）

用于服务间通过不可信网络通信的分布式部署：

```ini
# etc/conf/server.conf
enable_https=true
verify_client=true            # 要求来访方出示客户端证书
client_verify_server=true      # 连接其他服务时校验对方证书
access_password=<SHA-256哈希值>
persistence_mode=postgresql
```

所有服务在 TLS 握手阶段必须出示由可信 CA 签发的有效证书。跨团队证书配置见证书生成指南。

### 安全配置对照表

| 配置项 | 开发模式 | 生产模式（Nginx） | 高安全模式（分布式） |
|--------|---------|------------------|-------------------|
| `enable_https` | false | true | true |
| `verify_client` | false | false | true |
| `client_verify_server` | false | false | true |
| `access_password` | 空 | SHA-256 哈希 | SHA-256 哈希 |
| `persistence_mode` | file | postgresql | postgresql |
| 注册功能 | 不可用 | 可用 | 可用 |
| 前端 | HTTP | HTTPS（Nginx） | HTTPS（Nginx） |
| Nginx 证书 | 无需 | CA 签名 | CA 签名 |

### 生成自签名证书

用于开发或内部测试：

```bash
python -m generate_selfsign_cert etc/ssl serverAuth
```

新生成的 TLS 证书默认带 SAN：`DNS:localhost`、`IP:127.0.0.1`、`IP:::1`。
部署到其他地址时，用可重复的 `--dns` / `--ip` 指定实际访问地址；显式选项会替换默认 SAN 列表：

```bash
python -m generate_selfsign_cert etc/ssl-new serverAuth --dns orch.example.test --ip 192.0.2.10
```

SAN 必须与客户端 URL 的主机匹配，IP 必须使用 `--ip`，仅设置 CN 或信任证书不能解决 SAN 缺失。
旧证书不会自动更新；工具拒绝覆盖已有证书或私钥。已有部署请在新目录生成，备份并部署匹配的
证书/私钥后重启服务；需要重新分发信任证书的客户端应同步更新。不要覆盖用于校验客户端身份的 CA 信任库。
`dataSigning` 不添加 TLS SAN，也不接受命令行 SAN 选项。

生成 RSA 3072 位证书，满足内置证书校验要求。复制为配置期望的文件名：

```bash
cd etc/ssl
cp server_RSA.cer server.cer
cp server_key_RSA.pem server_key.pem
cp server.cer trust.cer
echo -n "<密码>" > cert_pwd
```

生产环境请使用受信任 CA 签发的证书（Let's Encrypt、阿里云 SSL 或企业内部 CA）。

### 跨节点部署与对接

客户端（如工作流执行引擎、调用编排 REST 接口的系统）与本服务不在同一节点时，需完成以下配置：

**1. 服务端绑定地址**

`etc/conf/server.conf` 默认 `ip=127.0.0.1`，仅监听回环地址，其他节点无法建立连接。跨节点部署时改为实际网卡 IP 或 `0.0.0.0`，并在节点间放通服务端口（默认 5001）。

**2. 证书 SAN 覆盖对端访问地址**

客户端 URL 中的主机名或 IP 必须出现在服务端证书的 SAN 中（生成命令见上文）。注意：

- 显式 `--dns` / `--ip` 会**替换**默认回环 SAN 列表；若仍需本机访问，请将 `localhost`、`127.0.0.1` 一并显式指定；
- 对端使用 IP 直连（如 `https://192.0.2.10:5001`）时必须用 `--ip` 添加该 IP，DNS SAN 与 IP SAN 不能互替。

**3. 客户端接入方式（自签名证书场景）**

| 方式 | 适用场景 | 说明 |
|---|---|---|
| 跳过证书链校验（如引擎侧 `sslVerify=false`） | 开发 / 测试 | 仅跳过证书链校验；多数客户端（尤其是 Java JDK HttpClient）仍会执行主机名校验，证书 SAN 依然必须匹配访问地址。两项校验相互独立，跳过其一不影响另一项 |
| 导入信任证书并开启校验 | 生产环境 | 将本服务的 `trust.cer` 导入客户端信任库，保持证书校验开启 |

Java 客户端导入信任库示例：

```bash
keytool -importcert -alias openan-orchestration -file trust.cer \
    -keystore client-trust.jks -storepass <密码> -noprompt
```

以工作流执行引擎对接为例，跨节点部署需同步调整：引擎侧编排中心地址（`orchUrl`）指向实际服务地址；开启校验时，将上述信任库配置到引擎的 CA 证书路径并启用 `sslVerify`。

若服务端开启双向认证（`verify_client=true`），客户端还须持有由 `trust.cer` 签发的客户端证书，否则 TLS 握手阶段即被拒绝，与客户端是否跳过校验无关。


## 3. 使用

### 3.1 前提条件

- 注册中心服务已启动并正常运行
- 编排中心后端服务已启动并正常运行
- 编排中心前端服务已成功启动
- 浏览器可正常访问编排中心前端页面

### 3.2 背景信息

编排中心提供三种工作流创建方式：

- **PDF 导入**：解析 PDF 文档中的流程描述，自动生成工作流
- **手动编排**：通过拖拽 Agent 卡片到画布并连线，可视化定义流程
- **自然语言生成**：输入业务意图描述，后端自动生成对应的工作流

执行工作流时，系统通过 SSE（Server-Sent Events）技术实时推送执行进度，前端可实时展示每个 Agent 的请求和响应。

### 3.3 使用限制

- 当前版本仅支持解析 PDF 文档中标题为 "5. Interaction Flow" 的章节
- 工作流 ID 在保存时自动生成，不支持自定义
- 示例脚本启动的 Agent 仅供 Demo 演示使用，生产环境需对接真实 Agent 服务

### 3.4 操作步骤

1. **访问编排中心界面**

   在浏览器中打开前端地址（开发环境 `http://localhost:3003`，生产环境 `https://your-domain.com`）。

2. **登录（如已开启认证）**

   如果配置了 `access_password` 或 `persistence_mode=postgresql`，将显示登录页面。输入用户名和密码访问主界面。

   - 默认管理员凭据：用户名 `admin`，密码 `OpenAN@2026`（PostgreSQL 模式下首次启动自动创建）。
   - 注册新账号（仅 PostgreSQL 模式）：在登录页面点击注册链接。
   - `file` 模式下用户名为 `admin`，密码为 `access_password` 配置的值（哈希前的原始密码）。
   - 修改 file 模式下的密码：运行 `python generate_access_password.py` 重新生成哈希值。

3. **配置服务地址（可选）**

   如果后端不在默认地址，点击登录页右下角（或主界面右上角）的齿轮图标，配置后端 IP、端口和连接模式（直连 IP 或 Nginx 网关）。
3. **查看 Agent 库**

   左侧区域展示全部Agent列表，支持按Agent名称或功能关键词进行搜索筛选；单击任意Agent后，右侧区域将展示该Agent的详细信息。

4. **创建新工作流**

   - 单击左侧上方的 `+` 按钮
   - 选择创建方式：

     | 方式 | 操作说明 |
     | --- | --- |
     | PDF 导入 | 上传 PDF 文件，系统自动解析并生成 PSOP |
     | 手动编排 | 将下方 Agent 卡片拖拽到画布，通过连线定义执行顺序；单击连线可设置跳转条件 |
     | 自然语言生成 | 输入业务意图描述，后台自动编排生成 PSOP |

    **PDF导入：**

    单击"SolutionPackage 导入"选项，选择一份 PDF 格式的文档上传，等待上传完成；
    上传完成后，用户可以编辑后再进行保存。

    **说明：** 支持导入的 PDF 文件必须是 SolutionPackage 类型。SolutionPackage 是 TM Forum 定义的标准解决方案包文档格式，用于描述电信行业的解决方案和交互流程。可在 [TM Forum 官网](https://www.tmforum.org/search?contentType=Asset&pageIndex=1&searchTerm=an%20l4%20solution%20package) 查阅相关标准文档和示例。
    
   **手动编排：**
    - 步骤一 添加Agent卡片：
    从界面下方区域将所需的 Agent 卡片拖拽至画布空白区域。
    - 步骤二 配置Agent技能：
    单击画布上已添加的Agent卡片，在弹出的选项中选择需要使用的技能项。
    - 步骤三 添加更多Agent：
    重复步骤一和步骤二，根据业务需求将多个Agent拖拽至画布。
    - 步骤四 连接Agent卡片：
    将鼠标悬停在某个 Agent 卡片右侧的“小蓝点”上，此时鼠标指针会变为“十”字形状。按住鼠标左键不放，拖动至另一张 Agent 卡片上，松开鼠标完成连线。
    - 步骤五 配置分支条件：
    单击需要配置分支的连线，在弹出窗中的“分支配置”提示框内输入跳转条件并保存。这样，后续执行将根据不同的条件走不同的分支路径。
    - 步骤六 保存工作流：
    所有配置完成后，单击画布上方的“保存”按钮，完成工作流的创建或更新。
    
    **自然语言生成：**

    单击“自然语言编排”选项，在弹出的输入框中输入一段自然语言描述，单击“GENERATE”按钮
    生成后的PSOP工作流会展示在当前窗口，默认是“编辑”状态，可以直接保存，也可以修改后再进行保存。

5. **保存工作流**

   完成编排后，系统自动保存或手动触发保存操作，返回的 `workflow_id` 可用于后续检索和执行。

6. **查看已有工作流**

   在左侧面板展示所有的PSOP，并通过上方的搜索框按名称快速查找。单击任一PSOP后，右侧区域将自动显示其详细信息。

7. **执行工作流**
- 在上方输入框中输入用户意图；
- 单击右侧的“检索工作流”按钮；
- 系统检索到对应PSOP后，左侧区域将显示该PSOP；
- 中间区域自动展示该PSOP对应的工作流；
- 单击左侧PSOP右侧的“▶”按钮，页面右侧将实时显示工作流的执行过程。

## 4. FAQ

### 4.1 为什么启动后左侧 Agent 库为空？

**现象描述**：进入编排中心界面后，左侧 Agent 库没有显示任何 Agent。

**可能原因**：

- 注册中心服务未启动
- 编排中心后端服务未正确配置注册中心地址
- 示例 Agent 服务未启动（演示环境）

1. 确认注册中心服务已正常启动
2. 检查编排中心后端配置文件中的注册中心地址是否正确
3. 如需查看 Demo，执行 `python -m samples.start_agents_server` 启动示例 Agent
